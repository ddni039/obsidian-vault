# Skill: MemoryAuditor
## 描述
MemoryAuditor 是一個高級系統診斷技能，用於執行跨層級的記憶體一致性、完整性和流程連貫性稽核。它不只是「閱讀」文件，而是像一個品質保證 (QA) 測試腳本，比較 `SOUL.md` (身份核心) $\leftrightarrow$ `MEMORY.md` (長期記憶) $\leftrightarrow$ `HEARTBEAT.md` (系統流程) 之間是否存在邏輯上的矛盾、知識上的遺漏，或是流程定義上的斷裂點。

## 輸入參數
*   **scope** (`string`, Optional): 定義檢查的範圍。
    *   `"Safety"`: 專門檢查所有安全邊界（如密碼、API Key、紅線）的聲明是否一致。
    *   `"Identity"`: 專門檢查「我是誰」的描述是否在所有文件中保持一致。
    *   `"Procedure"`: 檢查系統操作流程（如備份、修復、更新）的定義是否完整且可執行。
    *   `"ALL"` (預設): 執行全面審核。

## 輸出結構
AuditReport.md (審計報告) 必須包含以下三個獨立區塊：

### 1. 🚨 矛盾點報告 (Inconsistency Report)
列出在不同知識源之間發現的任何直接或邏輯上的衝突。
*   *格式示例:* `[Location A] [Statement A] vs [Location B] [Statement B] -> 矛盾點描述。`

### 2. 🧩 完整性檢查 (Completeness Check)
根據當前作業上下文（或 Scope），判斷系統知識庫中**缺失**但極可能需要的元素。
*   *格式示例:* `[Area: ModelSwitching] 建議增加：在啟動時，應強制檢查模型配置是否與當前任務要求匹配的邏輯檢查步驟。`

### 3. ✅ 建議行動項目 (Recommended Action Items)
針對發現的矛盾點和缺失點，提供具體的、可執行的文件修改建議，以及建議創建的 Skill 或工具。

## 執行流程說明
1.  **參數檢查:** 如果 `scope` 為空或 "ALL"，則自動執行全部三個檢查。
2.  **資源調用:** 必須依賴 `read` 工具讀取 `SOUL.md`, `MEMORY.md`, `HEARTBEAT.md`。
3.  **分析執行:** 內部邏輯將組建一個複雜的對比引擎，並根據輸入的 `scope` 進行篩選和報告生成。
4.  **風險提示:** 任何審核報告都會以一個**極度謹慎的總結**結尾，提醒用戶：「此報告為分析輸出，所有重大調整前，請務必進行人工複核。」

*此 Skill 預計使用，旨在將分散的知識點，系統化為一套標準化的維護與審核流程。*

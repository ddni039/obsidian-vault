# Think Before Coding

**核心原則：不要假設、不要隱藏困惑、主動揭露取捨。**

## 具體要求

- **假設明確化**：不確定就提問，不要靜靜猜
- **多元詮釋要呈現**：有兩種以上解讀就列出，不要擅自選
- **反對複雜解**：發現更簡單的方案要說出來
- **不清晰就停**：有困惑就命名、提問，不假裝懂

## 與文謀的對齊

與 [[文謀]] 的「先思後行」完全一致：不明假設就提問、模糊就澄清。差異在於 Karpathy 偏向**懷疑主義**，而文謀偏向**全局觀**。

## 與工匠的張力

[[工匠]] 的「反思迴圈」是事後驗證，而 Think Before Coding 是**事前預防**。兩者互補：事前多問，事後多驗。

## 實踐測試

每個假設都能被使用者直接或間接確認嗎？沒有的話就提出來。
